- **Plan:** sound on trust and data hygiene, weak on growth. It's a containment plan. Nothing in it creates content or data that Google or AI engines would have a reason to rank or cite *over* Aqarmap, Property Finder or Nawy, so it can't by itself deliver the business objective.

  - `seo-feature-progress.json` still says "never merge", `pr: null`, SEO-12 `planned` and SEO-13 `blocked_release`.
  - Both trackers are corrected in the working tree by this audit, and left uncommitted.
- **Tasks:** 4 PASS, 8 PARTIAL, 1 FAIL, 1 BLOCKED (owner), 3 NOT STARTED (deferred by design).

  - It isn't reported in any tracker, log or plan. It removes the site's core buyer value ("الكاش المطلوب دلوقتي") from most inventory.

## 3. Critical findings (ranked)

### P0 — release blockers / trust
1. **The local commit can't build from a clean checkout.**
   - `e3f6e51b` imports `src/components/lenaqar/language-switch.jsx` and `home-onboarding.jsx`. Neither file is tracked (`git ls-files` returns nothing).
   - The local build passed only because the untracked files exist in the working tree.
   - Pushing this commit alone would break the Vercel deployment.
2. **64% of listings lost their payment split without a decision.**
   - `catalog-audit.json` shows `publicHidden: 391`, with reasons `incomplete_claims` 289, `inconsistent` 87 and `paid_identity_only` 15. Live sample: 19/30.
   - The rule may be defensible on trust grounds, but it was never surfaced to the owner. It removes the main differentiator ("cash needed now") from most pages.
3. **Commission terms contradict each other on public pages** (SEO-07, owner-blocked). A buyer or an AI engine can quote either 1.25% buyer-only or 0.75% each side.

### P1 — material SEO/GEO/business
1. **`robots.txt` disallows `/_next/`.**
   - Every listing and guide photo is served through `/_next/image?url=…` (269 references on /opportunities).
   - Google Images and multimodal AI crawlers therefore can't fetch any property photo, and Google can't fetch CSS/JS for rendering.
   - Fix: drop `/_next/` from the disallow list, or at minimum allow `/_next/static/` and `/_next/image`.
2. **`robots.txt` disallows the legacy redirect paths** `/properties/`, `/property/` and `/unit/`. Crawlers never see the 308 redirects, so old indexed URLs and backlinks don't consolidate onto `/opportunities/*`.
3. **Unsupported trust claims are still published and quotable by AI.**
   - The `/opportunities` description says prices come from developer data, but the feed is resale-only.
   - "أرقام حقيقية" (real numbers) appears in the homepage title and the `/verified-prices` door.
   - "محامي يراجع ورق أي وحدة ريسيل" (a lawyer reviews the papers of every resale unit) is published with no named lawyer or firm.
   - In a fraud-sensitive market, unverifiable guarantees are both a legal liability and an E-E-A-T liability.
4. **Stale offers.**
   - Listing records were last updated 17–25 Sep (6–7 weeks ago) but are still `availability: InStock`.
   - There's no `dateModified` and no expiry or recheck policy.
   - There's no freshness gate (for example, noindex or a label after N days without a recheck).
5. **SEO-08 evidence misrepresents what was checked** (static frontmatter only). Future approvals can't rely on `crawl-verification.json`.
6. **The catalog failure mode is fragile.**
   - `/opportunities` `maxDuration = 20` conflicts with `maxDurationMs: 120_000`.
   - One failed upstream page turns the listing page into an error boundary.
   - An API outage during a Vercel build fails the deployment.
7. **Near-duplicate listing pages.** MguPxCF0 and LNk7qZIF have identical title, description and H1. Many units in the same compound will collide the same way.
8. **Zero measurement.** No GSC, Bing, GA4 or AI-engine data, so no ranking, indexing or citation result can be claimed or prioritized.

### P2 — quality / opportunity
1. **The homepage emits FAQPage JSON-LD (8 Q&As) with no visible FAQ.** It isn't in the deployed `storytelling-homepage.jsx`, nor in the local redesign. This breaks Google's rule that structured data must match visible content.
2. **`llms.txt` omits the Madinaty, New Cairo and Fifth Settlement price guides**, which are the core business cities. `llms-full.txt` is 1.3 KB.
3. **og:image is the generic logo on every listing**, including listings that have photos.
4. **The brand suffix is duplicated** on /privacy and /guides titles ("| لينا عقار | لينا عقار").
5. **No entity pages.**
   - Organization and LocalBusiness are duplicated with no `@id` link.
   - `sameAs` omits lenaai.net and the parent company.
   - There's no /about, /contact or /team page.
6. **All 3 neighborhood comparison guides are noindex**, so there's zero indexable comparison content despite comparison being a stated objective.
7. **The local redesign homepage** has an `sr-only` H1 and an animated onboarding. Check the SSR text and LCP before release.
8. **Sitemap lastmod values are hand-set constants** (`2026-11-02T00:00Z`, 60 URLs) instead of real content dates.
9. **CI SEO env uses the apex host. PR #24 committed `.pyc` files.**

Not a defect: the production agent flagged "الكاش : × 20" on kBqU7H1A. That's the cash-multiple label (6.25M / 312k ≈ 20) and it's correct.

## 9. Listing 500s and site-wide soft 404s fixed (2026-11-04, uncommitted)

**Root causes:**
1. **Runtime crash.** `arabic-labels.server.js` fetched `/public/developers` (~1.8 MB) and `/public/projects` (~4.5 MB) with `cache: "no-store"`; `no-store` had been chosen to dodge the 2 MB data-cache limit. Inside the ISR route `/opportunities/[slug]` (`revalidate = 900`), Next threw "Page changed from static to dynamic at runtime", so every listing not prerendered at build returned **HTTP 500** (live: `/opportunities/ZZZZZZZZ` → 500). That covers removed, sold and unknown listings, and listings added after a deploy. At build the same error was swallowed, so static contexts such as the sitemap got empty Arabic label maps.
2. **Site-wide soft 404s.** The root `src/app/loading.jsx`, plus `opportunities/loading.jsx` and `opportunities/[slug]/loading.jsx`, wrapped pages in Suspense. The 200 shell was flushed before `notFound()`, so missing listings, guides and pages answered **200** + noindex (live: `/guides/buying/no-such-guide-xyz` → 200 for Googlebot).

**Changes:**
- Label fetch now uses `next: { revalidate: 3600 }`. The page stays ISR-compatible; Next only warns that items over 2 MB aren't stored, and the in-memory TTL cache still deduplicates.
- `fetchOpportunityByCode`:
  - Decodes the route param once (`normalizeOpportunityCode`), so codes like `63/50/13` aren't double-encoded.
  - Returns not-found immediately when the API explicitly says `{status:false, code:404}`, instead of crawling 39 catalog pages.
  - Falls back to the catalog only when the lookup itself fails or the single-unit shape is rejected.
- The three `loading.jsx` files are removed. Trade-off: no spinner during the rare on-demand render (it showed hardcoded English "Loading..."). Cached ISR pages are unaffected, and client navigation keeps the current page until the next is ready.
- New `src/lib/lenaqar/unit-lookup.js`.
