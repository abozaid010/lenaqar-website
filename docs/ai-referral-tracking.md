## 1. Crawler access (checked live)

Ran `GET https://www.lenaqar.com/guides/madinaty/prices-2026` with each user agent. All returned **200**:

GPTBot · OAI-SearchBot · ChatGPT-User · ClaudeBot · Claude-SearchBot · Google-Extended · PerplexityBot · bingbot

- Hosting is **Vercel** (`server: Vercel` header, no Cloudflare headers). The Vercel Firewall rule set was **not** inspected. Check it in the Vercel dashboard: *Project → Firewall*. The 200 results above show no block today.

## 2. GA4 channel group "AI Referrals" (owner action)

GA4 property "lenaqar" (account abozaid.ibrahim11@gmail.com), measurement ID `G-3QC63HK3DQ`. Old shared property `G-L76Z647950` is no longer used by the site.

1. **Admin → Data display → Channel groups → Create new channel group** → name `AI Referrals`.
2. Add a channel named `AI Referrals`. Condition: **Session source matches regex**:

   ```
   chatgpt\.com|chat\.openai\.com|openai\.com|claude\.ai|anthropic\.com|gemini\.google\.com|bard\.google\.com|perplexity\.ai|copilot\.microsoft\.com|bing\.com
   ```

3. Move the channel **above** "Organic Search" so Google/Bing traffic is not caught by the default rule first.
4. Caveat: GA4 matches the **domain only**, not paths. `bing.com/chat` cannot be separated from ordinary Bing search, so the regex above counts all `bing.com` traffic as AI. Remove `bing\.com` if that is too broad.

## 4. UTM tags on links we control on third-party pages (owner action)

The repo has no app-store, directory or partner links. Its only external hosts are our own social profiles (Facebook, Instagram, TikTok, YouTube, LinkedIn), which live in the footer and are not third-party pages. **Owner to send a list** of every listing, directory or partner page that links to lenaqar.com.

Convention for those links (lowercase, no spaces, matches `docs/ads-utm-and-conversion.md`):

```
utm_source=<platform>&utm_medium=referral&utm_campaign=<placement>
```

Example: `?utm_source=aqarmap&utm_medium=referral&utm_campaign=profile`.
